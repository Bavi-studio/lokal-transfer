# Ручной интеграционный план: Windows 11 + iPhone

Этот документ — план проверок, а не отчёт об их выполнении. Каждую проверку отмечать выполненной только после фактического запуска и записи результата.

## Подготовка

1. На Windows установить Python 3.13 или 3.14 и зависимости: `python -m pip install -e ".[test]"`.
2. Запустить `python -m pytest -q` и сохранить вывод.
3. Убедиться, что токен хранится в `data/.access-token`, каталог доступен только владельцу Windows-профиля и не публикуется через HTTP.
4. Создать контрольный набор файлов: пустой файл, UTF-8 текст с кириллицей, бинарный файл, файл с Unicode-именем, файл размером 100 МБ и файл размером, близким к настроенному лимиту.
5. Для каждого файла вычислить SHA-256 в PowerShell: `Get-FileHash .\имя-файла -Algorithm SHA256`.

## Проверка 1 — loopback

1. Запустить сервер с `--host 127.0.0.1 --port 8000`.
2. Открыть `http://127.0.0.1:8000` на Windows.
3. Выполнить загрузку и скачивание контрольного файла через API или интерфейс.
4. Сверить SHA-256 исходного и скачанного файлов.
5. Ожидаемый результат: локальный доступ работает; доступ с iPhone к loopback Windows не предполагается.

## Проверка 2 — IPv4-адрес Wi-Fi-интерфейса

1. Выполнить `ipconfig` и записать IPv4-адрес адаптера, связанного с точкой доступа iPhone.
2. Запустить сервер с `--host <IPv4-адрес-Windows> --port 8000`.
3. Открыть `http://<IPv4-адрес-Windows>:8000` на самом Windows-компьютере.
4. Повторить загрузку, скачивание и проверку SHA-256.
5. Ожидаемый результат: сервер принимает соединения через выбранный интерфейс.

## Проверка 3 — точка доступа iPhone

1. Включить Personal Hotspot на iPhone и подключить Windows к этой сети.
2. Проверить IPv4-адрес Windows через `ipconfig` после подключения.
3. Запустить сервер на этом IPv4-адресе.
4. В Safari на iPhone открыть `http://<IPv4-адрес-Windows>:8000`.
5. Проверить пустой файл, бинарный файл, Unicode-имя, несколько файлов и скачивание на iPhone.
6. Проверить текст в обоих направлениях и повторить передачу после перезагрузки вкладки.
7. Ожидаемый результат: все содержимое совпадает; успешная загрузка подтверждается только после ответа сервера.

## Проверка 4 — Windows Firewall

1. При работающем сервере проверить доступность с iPhone при разрешающем правиле для частного интерфейса.
2. Временно отключить именно правило для порта 8000 или создать явное блокирующее правило; не отключать весь брандмауэр.
3. Убедиться, что соединение с iPhone блокируется, а loopback на Windows продолжает работать.
4. Вернуть исходное правило и проверить восстановление доступа.
5. Зафиксировать профиль сети, локальный порт, удалённый адрес и точное правило Firewall.

## Проверка 5 — большие файлы

1. Передать файл 100 МБ или больше, но меньше `LOCAL_TRANSFER_MAX_FILE_SIZE` и доступной квоты.
2. Во время передачи проверить прогресс, скорость и состояние временного файла; не считать файл завершённым до HTTP-ответа `201`.
3. Скачать файл обратно и сверить SHA-256.
4. Повторить с файлом выше лимита: ожидается `413`, в списке нет частичного файла, временный каталог очищен.
5. При необходимости провести отдельный тест близко к лимиту дискового пространства только на тестовом каталоге.

## Проверка 6 — временный сетевой разрыв

1. Начать загрузку крупного файла.
2. Во время передачи отключить Wi-Fi на iPhone на несколько секунд или выключить точку доступа.
3. Проверить, что интерфейс не показывает ложный успех, а незавершённый файл отсутствует в списке.
4. Восстановить сеть, повторно открыть страницу и обновить список.
5. Повторить передачу того же файла и сравнить SHA-256.
6. Проверить, что сервер продолжает принимать новые загрузки и временные файлы от прерванной операции не остаются после очистки/перезапуска.

## Фиксация результатов

Для каждого сценария записать дату, версию Windows, версию Python, модель iPhone/iOS, браузер, адрес интерфейса, размер файла, ожидаемый результат, фактический результат и SHA-256. Непроведённые сценарии отмечать как «не проверено», а не как успешные.
